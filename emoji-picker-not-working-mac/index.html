Emoji picker not working on Mac? Here’s the fix

Three different routes open the same picker, and which one fails tells you why. Run the 30-second test, then work down the fixes in the order they tend to be the answer.

By Wells Riley, who makes Mojito·Updated October 4, 2026·Tested on macOS 27

🌐fn E → 😀

Nothing? Also try ⌃ Control ⌘ Command Space and Edit › Emoji & Symbols. Which one fails tells you why.

Why won’t the emoji picker open on my Mac?

Usually one of three things: the 🌐 key was reassigned, an app switched on Secure Keyboard Entry, or another app took the shortcut. Try all three ways in: Fn + E, Control + Command + Space, and Edit › Emoji & Symbols. If only the 🌐 key fails, it’s the setting. If only ⌃⌘Space fails, an app grabbed it. If all three fail everywhere, it’s Secure Keyboard Entry.

With Mojito, emoji don’t go through Apple’s picker at all: type :smile and press Return for 😄. A reassigned key or a stolen shortcut can’t break that, though Secure Keyboard Entry blocks it too.

1. The 🌐 key was switched to something else

You’ll know it’s this if tapping 🌐 on its own does nothing or changes your keyboard language, while Fn + E still opens the picker. (If you type in two languages, Change Input Source may be what you want; keep it and use Fn-E for emoji.)

  1. Open System SettingsKeyboard.
  2. Find Press 🌐 key to. On keyboards without a Globe key it reads Press fn key to.
  3. Choose Show Emoji & Symbols, then tap 🌐 in a text field.

Odds are you didn’t change it on purpose. Apple documents the usual culprit: choosing a Dictation keyboard shortcut can change this setting automatically, so making “press 🌐 twice” your Dictation shortcut quietly turns the key into Start Dictation. To have both, give Dictation a shortcut that doesn’t use 🌐 under KeyboardDictationShortcut, then set the key back.

Apps that take over the 🌐 key set it to Do Nothing so macOS stays out of their way; Mojito’s Replace System Picker option does exactly that. Delete an app like that without undoing it first, and 🌐 does nothing until you change it back here.

2. Secure Keyboard Entry is on

You’ll know it’s this if nothing opens the picker, not even the Edit menu, in any app, and your text expander has gone quiet too.

Secure Keyboard Entry (“Secure Input” under the hood) is a lock any app can switch on so other software can’t read your typing. Password fields use it briefly. While it’s on, macOS shuts out every input helper: the emoji picker by every route, plus text expanders and tools like Mojito. Trouble starts when an app never lets go. Usual suspects:

  • Terminal: look at TerminalSecure Keyboard Entry. A checkmark means it’s on. iTerm2 has the same option in its app menu.
  • Cisco AnyConnect (now Cisco Secure Client), a VPN app many companies use, and Webroot antivirus.
  • Password managers, sometimes long after their unlock prompt has gone away.

To find out exactly which app is holding it:

  1. Open Terminal and run ioreg -l -w 0 | grep SecureInput. If it prints nothing, Secure Input is off; skip to fix 3.
  2. If it prints a long line, find "kCGSSessionSecureInputPID"= and the number after it, say 1234. That’s a PID (process ID), the number macOS gives every running program.
  3. Open Activity Monitor, choose ViewAll Processes, and click the PID column header to sort (missing? add it under ViewColumns). Your number’s row is the culprit. Or ask Terminal: ps -p 1234 -o comm=, using your number.
  4. Quit that app, or turn off its secure-entry setting, and press Fn + E again.

If the culprit turns out to be loginwindow, that’s macOS itself holding on, often after the lock screen. You can’t quit it; log out and back in instead (fix 5).

3. Another app took the shortcut

You’ll know it’s this if ⌃ ⌘ Space does nothing, or opens something else, while Fn-E and the Edit menu still work.

Don’t count on System SettingsKeyboardKeyboard Shortcuts… to flag it. That pane lists macOS’s own shortcuts and any App Shortcuts you’ve added, not the global hotkeys other apps register. Check the apps that hand out hotkeys: Raycast, Alfred, BetterTouchTool, Keyboard Maestro, window managers, IDEs with their own keymaps. Quickest test: quit them one at a time, pressing ⌃⌘Space after each, and change the hotkey in whichever one brings the picker back.

Mojito does this on purpose if you ask: its Replace System Picker option points ⌃⌘Space and 🌐 at Mojito’s emoji browser. The reset button next to Emoji Browser shortcut in its SettingsGeneral undoes both.

If Fn-E is the one that fails

Fn-E needs a keyboard that tells macOS when Fn is down, as the built-in keyboard and Apple’s keyboards do. Many third-party keyboards handle Fn internally, so macOS never hears it; Logitech, for one, says Apple’s Fn/Globe shortcuts aren’t supported on its keyboards. A remapper like Karabiner-Elements can intercept Fn too. On those setups, use ⌃⌘Space.

4. It’s opening where you can’t see it

You’ll know it’s this if the picker works when the app is in a normal window but not in full screen, or it turns up on your other display.

The picker comes in two sizes. The small one is anchored to your text cursor. The big one, the Character Viewer behind the expand button in the top-right corner, is a free-floating window, and macOS remembers that you last used it and where you left it. It doesn’t always follow you into a full-screen app, and if you left it on an external display or a Sidecar iPad, that’s where it opens. (More on the two pickers.)

  1. Leave full screen with ⌃ ⌘ F (or the green window button), or look on your other display. If that display is gone, plug it back in once.
  2. Open the picker. If you get the big Character Viewer, drag it into view if needed and click the button in its top-right corner to shrink it back to the small picker.
  3. Go back to full screen. The small picker sits at your cursor, so it should appear there.

5. Log out and back in, or restart

If nothing above fits, log out and back in from the Apple menu. A fresh session clears a Secure Input lock stuck on loginwindow and restarts the background processes behind the picker. Still broken? Restart. If the picker then works in safe mode, which skips login items, something that launches at login is interfering: turn items in System SettingsGeneralLogin Items & Extensions back on a few at a time to find it.

Or skip the system picker

Every fix above gets Apple’s picker working again. The alternative is one that doesn’t depend on it. Mojito is a free, open-source app that works the way Slack does: type a colon and a few letters in any app, and matches appear at your cursor. :smile plus Return gives you 😄. It never touches the 🌐 key, ⌃⌘Space, or the Character Viewer, so fixes 1, 3, and 4 can’t happen to it. The codes are the ones Slack and GitHub use (cheat sheet).

The limits, plainly: Mojito reads keystrokes, so Secure Keyboard Entry blocks it just as it blocks Apple’s picker (fix 2 still applies). More picker questions

Why does the picker work everywhere except one app?

Password fields block it on purpose. Otherwise the app may have its own secure-entry option on (Terminal’s is in its app menu), be in full screen (fix 4), or draw its own text fields instead of using the Mac’s, as many games and remote-desktop windows do.

Did macOS 27 change the emoji shortcuts?

No. Fn + E, ⌃ ⌘ Space, and the 🌐 setting work as before. The picker got Apple’s glass look and, on Macs with Apple Intelligence, a Genmoji button in its top-right corner.
